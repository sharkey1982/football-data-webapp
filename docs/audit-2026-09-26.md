# Catalogue audit findings, 2026-09-26

Found while writing the data catalogue (`docs/catalogue.md`) and methodology (`docs/methodology/`) from the code and the live definitions. Nothing here has been fixed yet. Model-quality issues are in `docs/methodology/README.md` → "Known limitations"; this file holds the rest. **Verified** means it was confirmed against live data or the live definition, not only read in code.

## Security

1. **`meta_refresh_flow()` admin guard always passes.** It is `SECURITY DEFINER` and checks `current_user in ('postgres','service_role')`. Inside a definer function `current_user` is the owner, so any signed-in user can run it (execute is granted to `authenticated`). Use `_require_admin()` or `session_user`. **Verified** in `supabase/definitions/functions/meta_refresh_flow.sql:12`.
2. **`get_tactical_role_worklist` is executable by anon.** It serves an admin page, but execute is granted to PUBLIC/anon (`supabase/schema/public.sql` ~7797).
3. **`/admin/model` and `/data-health` have no route guard.** Only the nav link is hidden (`src/App.tsx`). The tables they read are anon-readable, so this is information exposure rather than write access.

## Data correctness (live)

4. **FIXED 2026-09-26 (migration 20260926170000).** **`lineup_confidence` mismatch.** The v6 refresh maps `'consensus_v3'` to 0.90, but the views emit `'lineup_consensus_v3'`, so consensus-placed players get 0.55. **Verified**: 65 live `leaguewide_v6` rows have `minutes_source = 'lineup_consensus_v3'` and `lineup_confidence = 0.55`.
5. **FIXED 2026-09-26 (migration 20260926170000): upcoming fixtures with a formation 50 → 326.** **Manual formations can be ignored.** `fixture_team_tactical_consensus` only uses its manual and default-formation branches when a `leaguewide_v4` projection exists for the fixture (lines 26 and 48). v4 is retired, so admin formation edits may not reach newer fixtures. **Verified** that the condition is present; the effect is not yet checked against data.
6. **Odds are not refreshed.** `backfill_match_odds()` is the only writer of `match_odds`, and nothing schedules it. Recent matches probably have no odds, which affects the betting and market-efficiency pages.
7. **`league_standings.tier` is `league_id`.** This is right for England (1–5) and wrong elsewhere (e.g. La Liga shows tier 13).
8. **Fixture status can say `played` before a result exists.** Both `refresh_fixture_feeds()` and `refresh_feed_nearest_date()` mark past kick-offs as played. This is linked to the open 2026-09-23 incident.
9. **`result_ingestion_runs` holds junk rows** (11–17 Sep) from the retired `ingest-football-results` stub. That edge function still needs deleting in the dashboard.

## Season rollover (2027/28), in addition to the known single-column FPL keys

10. **Hard-coded season 13 / `'2627'`.** Found in:
    - `src/lib/tacticalRoleAdminApi.ts` (lines 169, 368, 375)
    - `refresh_fixture_feeds()` and `refresh_feed_nearest_date()` (`'2627'`)
    - `refresh_scottish_premiership_fixtures()` (`scottish-premiership-2026`)
    - `refresh_fpl_projections_range`, `get_betting_*`, `get_model_xi_*` (default season 13)
    - scripts using season 13
11. **Joins on `fpl_player_id` without `season_id`.** `fpl_players` is keyed `(fpl_player_id, season_id)`, but these join it on `fpl_player_id` alone:
    - `get_actual_value_table`
    - `get_daily_digest`
    - `get_gameweek_digest`
    - `get_digest_gameweeks`
    - `get_fpl_market_movers`
    - `get_injury_report`
    - `get_price_change_risk`
    - `get_tactical_role_worklist`
    - `get_team_of_the_week` (live branch)
    - `get_totw_vs_model`
    - `fixture_player_lineup_consensus`
    - `fixture_player_expected_minutes_v2`

    These are harmless with one season loaded, but will duplicate or mis-join once there are two.
12. **Season parameter ignored.** `get_daily_digest(p_season_id)` and `get_price_change_risk(p_season_id)` never use `p_season_id`.

## Rules breached

13. **`get_totw_vs_model` breaks two rules.** Its model XI has no 3-per-club limit, and it uses the current projection row without a `generated_at < kickoff` filter, which is a hindsight risk. `fpl_projection_snapshots` (from GW6) is now the honest source.

## Housekeeping

14. **Unused or superseded objects** are marked `unused`/`superseded` in the catalogue (30 unused, 9 superseded). Candidates to drop:
    - the five `backup_*` tables
    - `fpl_projection_frontend_feed` and `fpl_optimizer_candidate_feed_v1` (both v4)
    - `fixture_player_expected_minutes` (v1)
    - `refresh_fpl_bonus_v3_for_fixture`
    - `backfill_historic_fixture_predictions`
    - `broadcast_confidence_rank`
15. **Misleading names.**
    - `get_all_time_top_scorers` returns teams, not players.
    - `team_home_away_adjustment_experimental_v1` is live, not experimental.
    - `get_top_actual_fpl_scorer` groups by `web_name`.
16. **`supabase/schema/public.sql` is stale.** It is dated 2026-09-21; the `meta_flow_*`, snapshot, broadcast and model-versioning tables exist only in migrations.
17. **Curated fantasy inputs have no writer in the repo.** These are the lineup predictions, squad hierarchy, tactical profiles and role priors, which are populated ad hoc. How they are refreshed should be written down before the AI Lab explains projections built on them.
